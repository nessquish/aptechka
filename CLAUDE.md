# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Десктопное приложение «Моя аптечка» (учёт лекарств, сроков годности, списка покупок) на Python 3.9+ и PySide6 (Qt) с локальной базой SQLite. Учебный проект; код, комментарии, docstring и тексты интерфейса — на русском, сообщения коммитов тоже. Ответы пользователю и новые комментарии пишите по-русски.

## Команды

Окружение лежит в `.venv`; на Windows запускайте через `.venv\Scripts\python.exe`.

```powershell
python -m pharmacy                       # запуск приложения
python -m pharmacy.db.seed               # демо-пользователь и базовые данные (нужно один раз)
python -m pharmacy.db.seed --full        # демо-аккаунт nessquish / demo12345 со всеми видами данных
python -m pharmacy.db.seed --reset --full  # то же, с чистой базы

python -m unittest                       # все тесты (около 2 минут), pytest не используется
python -m unittest tests.test_ui_settings                          # один модуль
python -m unittest tests.test_ui_settings.AccountTest.test_logout_asks_for_confirmation  # один тест
python -m black . ; python -m flake8     # линтеры (88 символов); pre-commit запускает их при коммите

python packaging\build_exe.py            # dist\Aptechka.exe (PyInstaller)
python packaging\build_exe.py --demo     # dist\Aptechka-Demo.exe с готовым тестовым аккаунтом
```

Коммит не проходит, если `black` или `flake8` что-то меняют или находят: исправьте и коммитьте заново. В рабочей копии файлы с LF (`core.autocrlf=true`, git при коммите предупреждает о смене переводов строк — это нормально).

## Архитектура

Четыре слоя, зависимости идут строго сверху вниз:

1. **`pharmacy/db`**: `Database` (`connection.py`) — единственная точка доступа к SQLite. Каждая операция открывает короткое соединение; `transaction()` даёт общую транзакцию. Схема в `schema.py` по ER-диаграмме и **не меняется** (миграций нет): всё, что не входит в схему (размер текста, тема «системная», значки меню, общие настройки уведомлений, масштаб), хранится в JSON-файле предпочтений рядом с базой. Путь к базе: `APTECHKA_DB` → `data/aptechka.db`, в собранном `.exe` — `%LOCALAPPDATA%\Моя аптечка` (у демо-сборки своя папка).
2. **`pharmacy/repositories`**: один класс на таблицу, только SQL, все запросы ограничены `user_id`. Принимают необязательное `conn`, чтобы участвовать во внешней транзакции.
3. **`pharmacy/services`**: бизнес-правила, проверки ввода (`ValidationError`/`NotFoundError` из `errors.py`, у ошибки есть `.field`, по которому UI подсвечивает поле). Сервис, меняющий данные, одной транзакцией пишет и сами данные, и запись в историю. `container.build_services(db)` собирает все сервисы в `Services`; интерфейс знает только о нём. Уведомления не копятся, а **пересчитываются** из состояния товаров (`NotificationService.refresh`), поэтому после изменения товара, настроек или списка нужно звать `refresh`. Состояние товара (`status.py`) — чистая функция от срока годности, остатка и «за сколько дней предупреждать», в базе не хранится.
4. **`pharmacy/ui`**: окно `App` (`app.py`) хранит сервисы, пользователя и предпочтения и сменяет экраны; после входа показывает `MainShell` (`screens/shell.py`: боковое меню + прокручиваемая область раздела). Экраны в `screens/`, переиспользуемые виджеты в `widgets/`.

### Особенности интерфейса, которые нужно знать

- **Всё рисуется кодом**: кнопки, поля, карточки, таблицы и иконки (`paint.py`, `icons.py`, `widgets/`) — не стандартные виджеты Qt и не QSS. Цвета только из `theme.palette()`, размеры шрифтов и высоты строк из `theme.TYPOGRAPHY`/`LINE_HEIGHTS`, шрифты через `fonts.font(style)`. Палитра и размер текста читаются **при создании виджетов**, поэтому смена темы/размера текста/значков перестраивает всё окно (`App.apply_user_changes`), а не перекрашивает виджеты.
- **Диалоги и выпадающие списки — обычные виджеты внутри главного окна** (`Modal`, `Dialog`, `PopupList`), а не отдельные окна. `Dialog(info=True)` — сообщение с одной кнопкой.
- **Масштаб**: `scaling.apply_scale_factor` выставляет `QT_SCALE_FACTOR` **до** создания `QApplication` (ручной масштаб читается из предпочтений до открытия окна); на лету его менять нельзя, поэтому настройка предлагает перезапуск. Экран узнаётся во вспомогательном процессе, потому что Qt запоминает масштаб при первом запуске.
- **Тема**: у пользователя в базе `light`/`dark`; режим «системная» хранится в предпочтениях (`theme_mode`), реальная тема вычисляется в `App.resolve_theme`, за сменой системной темы следит таймер в `App`. Экраны входа и регистрации всегда следуют системной теме.
- **Предпочтения** (`preferences.py`): JSON по ключу пользователя; пользователь `0` (`GLOBAL_USER`) — общие настройки (масштаб). Ключи вынесены в `preferences.py`, чтобы не было циклических импортов с `shell`/`settings`.
- **Таблицы** (`widgets/table.py`, `DataTable`): число строк на странице подгоняется под высоту окна (`paging.py`, `fit_rows` на экране, пересчёт из `MainShell.resizeEvent`); с `selectable=True` слева идёт столбец флажков, который **не входит в нумерацию столбцов** в публичных методах. Шапки страниц и панели переносят правую часть на вторую строку в узком окне (`widgets/wrap.py`); длинные подписи обрезаются (`ElidedLabel` в `widgets/common.py`).
- **Запомнить устройство** (`remember.py`): в файле только номер пользователя, срок и отпечаток хэша пароля; смена пароля обнуляет запись. Настоящий пароль нигде не хранится (в сеансе `App.session_password`, пока человек не вошёл без пароля).
- Данные профиля в настройках (`screens/settings.py`) применяются сразу, кроме окон смены имени/логина/почты/пароля; после пересборки окна раздел настроек открывается снова через `App.reopen_settings`.

### Тесты

- Запускаются через `unittest`; `tests/__init__.py` ставит малое число итераций хэша пароля, а UI-тесты идут на платформе `offscreen` (`tests/qt_helpers.py`: `ShellTestCase` — приложение с демо-данными и входом, `settle()` прокачивает события, `click()` шлёт мышиные события).
- `qt_helpers` выключает подгонку страниц по высоте (`paging.AUTO_FIT = False`), поэтому в тестах страницы по 8 строк; тест, которому нужна подгонка, включает её сам.
- `demo/aptechka_demo.db` — готовая база тестового аккаунта (в `.gitignore` только `data/`); сроки в ней задаются на день создания, свежие данные даёт `seed --reset --full`.
- При изменении текстов интерфейса и подписей обновляйте тесты: многие проверяют строки.
